# 通知规格

每条通知的触发条件、去重键与推送级别。修改文案请同时更新本文件。

## 推送级别说明

Bark 的 `level` 决定打扰程度：

| 级别 | 表现 | 本项目用于 |
|---|---|---|
| `passive` | 静默投递，不弹窗不响铃，进通知中心 | 行程结束 |
| `active` | 正常弹窗 | 充电、胎压、小结、月报、可能没锁车 |
| `timeSensitive` | 专注模式也能弹出 | 充电中断、低电量、哨兵告警 |

`critical` 级别未使用——它会绕过静音开关，容易造成骚扰，只在真正紧急的场景才值得。

## 行程结束

**触发**：数据库轮询发现一段行程已结束并完成边界判定。

**去重键**：`trip:<tripKey>`

```
🚗 行程结束 · 2.6 km
🕐 08:21 → 08:26 · 5 分钟
📍 海天路 → 小港街道
⚡ 0.34 kWh · 131 Wh/km · ¥0.12
🔋 电量 93% → 92% · 续航 362 → 359 km
⛽ 油车 ¥1.28–1.65 · 省 ¥1.16
```

**字段来源**：

| 行 | 来源 |
|---|---|
| 距离、时长 | `drives` 聚合 |
| 起终点 | `addresses.road`，为空时回退 `display_name` |
| 能耗 | 优先功率积分（`positions.power`），回退续航差 × 效率 |
| 平均能耗 | 能耗 ÷ 距离，**里程小于 1 km 不显示**（短途会算出失真值）|
| 电量 | 起点/终点 `positions.battery_level` |
| 续航 | `drives.start_ideal_range_km` / `end_ideal_range_km` |
| 电费 | 净耗电 × 电价 |
| 油车对比 | 同里程下家用车油耗区间 |

**省略规则**：任意一行缺数据时整行不输出，不会出现空值或 `undefined`。

## 充电：开始 / 即将充满 / 完成

**触发**：MQTT 的 `charging_state` 变化；数据库轮询作为兜底。

**去重键**：`charging:<key>:<type>`

```
🔌 开始充电
⚡ 27.04 kWh · 45% → 95%
```

完成时：

```
✅ 充电完成
⚡ 27.04 kWh · 45% → 95%
🔋 续航 174 → 370 km（+196）
📈 平均 4.0 kW · 7 小时 40 分
💰 电费约 ¥9.73
📍 小港街道
```

**电量与续航**：来自 MQTT 快照，缺失时用 `charging_processes` 补。

---

## 充电意外中断

**触发**：充电结束事件中，`结束电量 < 设定上限 - 5%`。

**去重键**：`charging:<key>:interrupted`

```
⚠️ 充电意外中断
🔋 62% / 目标 95%
⚡ 已充 18.20 kWh · 2 小时 10 分
📍 小港街道
👉 请检查充电桩或插枪状态
```

**已知限制**：设定上限（`charge_limit_soc`）只存在于实时数据流，数据库不存。容器重启后若该值尚未收到，无法判定中断，会退化成普通「充电完成」。

**为什么是 5%**：留出容差，避免「设 90% 充到 88% 就走」这种正常操作被误报为中断。

## 哨兵

**触发**：
- 开关：`sentry_mode` 值变化
- 疑似触发：哨兵开启期间，车辆从 `asleep` 变为非 `asleep`
- 被解锁：哨兵开启期间，`locked` 由 true 变 false

**去重键**：`sentry:<key>:<kind>`；「触发」另有 3 分钟冷却。

```
👀 哨兵疑似被触发
🕐 14:32
👉 建议查看车机录像
```

**限制**：TeslaMate 只能提供哨兵的开关状态，拿不到「录了几段视频」。这里的「触发」是「车辆被唤醒」的近似判断。

## 胎压

**触发**：任一轮胎低于 `TPMS_THRESHOLD_BAR`（默认 2.6）。

**去重键**：`tpms:<轮位>:<日期>` —— 同一条轮胎每天最多提醒一次。

```
🛞 胎压偏低
⚠️ 左后 2.42 bar（阈值 2.60）
👉 建议尽快补气
```

**数据来源**：`positions.tpms_pressure_fl/fr/rl/rr`（bar）。

**新鲜度保护**：最新一条胎压数据超过 6 小时则不判断，避免用车停了几天后拿旧数据误报。

**为什么不用「标准 2.9」**：标准胎压随季节与温度上下浮动约 0.3 bar，用标准值判断会大面积误报。2.6 是「怀疑扎钉」的下限，不是车厂标准。

## 低电量未充电

**触发**：以下条件**同时**满足

- 时间 ≥ `LOW_BATTERY_HOUR`（默认 21:00）
- 电量 ≤ `LOW_BATTERY_PERCENT`（默认 20%）
- 未在充电、未在行驶
- 停在名为 `home` 的地理围栏内

**去重键**：`low-battery:<日期>`

```
🪫 电量偏低且未充电
🔋 当前 15%
📍 车在家，建议现在插枪
```

**为什么限定在家**：在外面没电也无法立即处理，提醒只会制造焦虑。

## 可能没锁车

**推送级别**：`active`

**触发**：以下条件**同时**满足

- 最近一段行程已结束，且停车超过 `UNLOCK_ALERT_MINUTES`（默认 30 分钟）
- 车辆当前状态仍是 `online`（没进入 `offline` / `asleep`）
- 这段 `online` 是从停车那一刻就开始的（不是中途被 App 或哨兵唤醒）
- 不在充电、不在行驶
- 最近 30 分钟内没有充电结束

**去重键**：`unlocked:<行程 id>` —— 每次停车最多提醒一次。

```
🔓 车辆可能没锁
🕐 已停车 34 分钟，车辆仍在唤醒状态
🏠 停在家附近
👉 锁车后车辆通常 15 分钟内休眠，请确认是否已锁
```

**为什么这样判断**：TeslaMate 的 `positions` 没有 `locked` 列，MQTT 也不发布锁车状态，所以无法直接读到「是否已锁」。但车辆行为本身是可靠信号——锁车后约 15 分钟必然休眠，未锁车时车机保持唤醒等待无钥匙进入，会一直停在 `online`。

实测一辆车 90 天 198 次真正停车，**排除充电后 100% 都在 30 分钟内休眠**，仅有的 27 次「超过 30 分钟仍 online」全部发生在充电过程中。因此这条规则误报率极低。

**已知的误报场景**：人还坐在车里吹空调或听歌（这时确实没锁）；车辆正在 OTA 升级。

**数据来源**：`drives.end_date` + `states.state` + `charging_processes`。

## 每日小结

**触发**：从 `DAILY_SUMMARY_HOUR`（默认 21:00）起，**每小时尝试一次**；若车辆正在行驶则顺延到下一小时，直到停车。

跨零点处理：0 点、1 点各给一次补发机会，避免整天数据丢失。

**去重键**：`daily:<日期>`

```
📅 11 月 27 日小结
🚗 2 趟 · 8.0 km
⏱ 24 分钟
⚡ 1.4 度 · 电费 ¥0.50
🔋 当前电量 92%
```

没有出行时：

```
📅 11 月 27 日小结
💤 今天没有出行
🔋 当前电量 64%
```

## 月度报告

**触发**：每月 1 号 08:00，统计上一个自然月；当天错过则在之后任意时刻补发。

**去重键**：`monthly:<年>-<月>`

```
📊 10 月驾驶报告
🚗 165 趟 · 1,746 km
⏱ 56 小时 15 分 · 均速 31 km/h
⚡ 行驶能耗 243.6 度
⛽ 油车 ¥859–1,107 · 省 ¥746
🔌 充电 10 次 · 314.9 度
💰 预估电费 ¥113.36（0.36 元/度）
```

**电费口径**：按当月充入电量 × 电价。比「行驶净耗电 × 电价」更贴近真实支出——差额来自充电损耗与停车期间的电耗。

**无数据月份**：标记为已发送，不重试。
